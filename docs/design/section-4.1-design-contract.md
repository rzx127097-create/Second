# 4.1 问题描述与空地协同保障机制设计：设计契约

## 1. 证据等级与用途

- 当前成熟度：M1（模型规格与验收口径已冻结）。
- 本节用途：定义有限机载药液、道路约束移动补给和车机接驳服务如何共同改变协同施药问题。
- 允许表述：构建、设计、刻画、用于后续验证、可能改善。
- 禁止表述：显著提升、证明优于、全面最优、真实部署。

## 2. 系统边界

1. 作业系统由动态虫害场、多架植保无人机、可通行道路网络和移动药液补给车构成。
2. 主实验采用一辆移动药液补给车；数学符号保留多车扩展能力。
3. 移动补给车只补充农药，不承担电池更换、充电或其他物资保障。
4. 无人机在二维农田栅格内移动和施药；车辆只能沿道路拓扑运动。
5. OSM 道路用于构造路网约束仿真输入，不表述为真实田间部署证据。
6. 决策层选择服务请求或候选接驳点；车辆在道路上的低层运动由确定性最短路执行。
7. 生态积分步长与物理决策时间步长分别定义，二者不得混用。

## 3. 服务协议

服务流程为：

```text
请求生成 -> 请求开放 -> 分配/预约 -> 车辆沿路网行驶
-> 车机联合到达 -> 服务锁定 -> 药液转移 -> 恢复施药
```

- 请求触发依据是“剩余可施药时间”与“预计接驳、排队和服务时间”的比较，而非固定药量阈值。
- 服务开始必须满足接驳距离、请求归属、库存和服务状态等前置条件。
- 服务锁定是显式状态，服务期间动作可行域同步变化；不得由环境静默覆盖策略动作。
- 实际转移量同时受无人机缺口、车辆剩余库存和单次服务能力约束。
- 允许部分补给；库存耗尽不直接终止回合，系统继续执行剩余可行动作。

## 4. 参数冻结规则

以下参数仅定义符号和单位，不在 4.1 中虚构数值：

- 无人机载药容量（L）；
- 车辆初始药液库存（L）；
- 无人机和车辆速度（m/s）；
- 补给速率（L/s）；
- 服务准备时间（s）；
- 接驳服务半径（m）；
- 单次服务最大补给量（L）；
- 决策时间步长和生态积分步长（s）。

正式取值应在 4.5.1 中依据设备资料、田间研究或专家确认范围进行标定，并在正式实验前冻结。

## 5. 章节论证链

```text
有限机载药液
-> 无人机产生时空相关的动态补给需求
-> 固定保障可能引入额外接驳航程、等待和施药中断
-> 路网约束车辆向需求位置移动
-> 形成异构主体间的时间、空间和资源耦合
-> 需要联合优化施药任务与移动保障决策
```

“接驳距离缩短—等待减少—有效施药时间增加—治理效果可能改善”是后续实验待检验的机制链，而非本节预设结论。
