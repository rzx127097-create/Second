### Engineering-parameter registry

The registry now contains the eleven parameters required by the Section 4.2
contract:

`uav_onboard_pesticide`, `uav_usable_fraction`, `uav_spray_flow`, `uav_speed`,
`vehicle_inventory`, `vehicle_service_capacity`, `vehicle_transfer_rate`,
`service_setup_time`, `rendezvous_radius`, `vehicle_speed`, and `decision_dt`.

`vehicle_service_capacity` is kept separate from total vehicle inventory. The
scenario factory enforces `0 < vehicle_service_capacity <= vehicle_inventory`
and passes the value into the resource state. This prevents a single-service
limit from being silently equated with the tank inventory.

The parameter audit is currently **provisional** for all eleven entries. Each
record still points to a pending equipment/field source, so no value may be
described as a calibrated engineering constant in the thesis.

### Resource-activation pilot

The deterministic pilot command was run at scale `s1`, one episode, 160 steps:

```powershell
python scripts/run_resource_pilot.py `
  --config-dir configs `
  --output runs/resource-pilot-s1/raw.jsonl `
  --report runs/resource-pilot-s1/activation.json `
  --scale s1 --episodes 1 --max-steps 160
```

The pilot reports `activated: true` with an activation fraction of `0.75`.
Finite no-support and fixed-support conditions generated requests and pesticide
disabled time; mobile support generated requests and waiting time; the
teleport diagnostic transferred pesticide without vehicle travel. The
diagnosis is `resource_constraint_activated_unclassified`: the scripted policy
did not produce a causal endpoint improvement, and mobile transfer was zero in
this short run. These rows establish that the event and conservation mechanism
can activate; they do **not** establish a mobility benefit or a treatment
superiority claim.
